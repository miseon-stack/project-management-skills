# 决策与话术手册

两份内容：**怎么给建议**（对内） + **怎么开口**（对外）。所有对外表述默认客户会逐字读到。

---

## A. 决策建议：从「信号」到「该做什么」

每条差异都必须落到 **一个动作 + 一个负责人 + 一个期限**，否则不算建议。

| 信号 | 判读 | 建议动作（对内） | 对外怎么说 |
|---|---|---|---|
| 逾期未闭环 | 计划日已过、状态未完成 | 先问自己：是我们卡住还是客户卡住？我们卡住→今天给新排期；客户卡住→今天发请求 | 「本项计划完成日为 X，当前仍在推进，最新时间点我们整理后同步」 |
| 节点临近 | ≤3 天到期 | 当天确认能否收口；不能就提前改期，**不要等逾期** | 「为保障 X 节点质量，建议把本项完成时间调整为 Y，原因是…」 |
| 阻塞 / 待确认 | 状态含阻塞、或卡在客户未回复 | 明确「解铃人」是谁；把请求拆到最小可执行动作 | 「需要请贵方协助确认 A 与 B，我们即可继续推进」 |
| 进展空缺 | 表里有任务但没写进展 | 先取证再补，不编 | 直接补「日期 + 事实 + 下一步」 |
| 疑似已完成未回写 | 数据源出现完成迹象 | **翻到该群最后一轮对话找客户方确认语**，再定状态 | 不对外说「我们漏更新」，直接改成已完成并补一句事实 |
| 整表停更 ≥3 天 | 客户看到的是假表 | 立刻跑一轮回写（skill `feishu-project-table-sync`） | 不解释，直接更新 |
| 表内缺录 | 数据源有事、表里没有 | 逐条判定：要不要进表？进则补，不进则不补（成本类事项通常不进共享表） | 视事项性质决定是否对外提 |
| 风险词命中 | 客户出现不满意/催办 | 当天响应，先给可控动作，别解释 | 「今天先做 X，明天给你结果」 |

### 判定完成的三条纪律

1. **客户方最后一句正面反馈**才算完成（「谢谢，很清晰」「已经可以用了」），我方内部 Demo 不算。
2. 「拿到材料」≠「完成验证」；「单项初测通过」≠「客户验收」。
3. 状态拿不准 → **不动**，只在备注留痕，并写进巡检报告的待确认项。

### 建议的排序原则

先做**客户能感知**的，再做**表内好看**的：
1. 客户被卡住的请求（阻塞项） → 2. 即将到期的硬节点 → 3. 客户情绪风险 → 4. 表内一致性。

## B. 对外话术模板

### B1. 群内进展同步（每期固定格式，1 条消息讲完）

```
【<项目简称>】<日期> 进展同步

· <编号> <事项>
  <一句事实：做了什么 / 现在什么状态>
  <交付物名称>：<链接>

· <编号> <事项>
  …

下一步：
1. …
2. …

需要确认：
1. 请<对方角色>确认…
```

**硬规则**
- 每条事项 **≤ 2 句**，全文 **≤ 400 字**，链接独占一行。
- 只写双方确认过的事实与分工；不写内部判断、评价、差距分析。
- 不写：付款/催款/商务、我方投入量、内部分工指派、对客户方表格的评判、`rec…` 记录号。
- 逾期可提，但用中性表述：「计划完成日为 X，当前仍在推进」。
- 待确认项用**请求式**：「需要请贵方协助确认 A」，不写「请尽快」「务必」。

### B2. 交付物同步（方案/工具类）

```
<日期> 已交付：<交付物名称>
<链接>

覆盖范围：<3–5 个要点>
需要贵方：<明确到人 / 到动作的 1–2 项>
```

### B3. 节点变更或风险提示

```
关于 <事项> 的时间安排：
原计划 <日期>，结合 <客观原因>，建议调整为 <新日期>。
此调整不影响 <不变的验收范围 / 交付内容>。
如无异议我们按新时间推进。
```

### B4. 会议邀请 / 三方对齐

```
<主题> 对齐会（<日期> <时段>）
需要拉通：<角色 1> / <角色 2> / <角色 3>
会上需要定：① <边界/责任> ② <接口/口径> ③ <时间点>
会前材料：<链接>
```

## C. 群内「存档共识」怎么做

目的：把已发生的事实与双方认可的分工**固化下来**，避免后续扯皮。

1. **先发进展同步消息**（B1），让事实在群里可见。
2. **再发一条短确认**：「以上为截至 <日期> 的进展，如有出入请指出，无异议我们按此推进。」
3. **把消息原文摘录**（时间 + 发言人 + 原句）写进 `存档材料-<项目>-<日期>.md` 的「共识证据」段。
4. 若涉及**责任边界**（例如中间件由谁开发），必须单独发一条明确表述并 @ 对方负责人，得到回复后再存档。

⚠️ **默认不自动发送**。任何群消息先出草稿 → 用户确认 → 再发。发送走 `lark-cli im`，@ 人需要在消息里带 `ou_` 提及结构。
