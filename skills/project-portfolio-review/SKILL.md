# Project portfolio review

Build a decision-oriented portfolio view from the latest available project sources.

## Workflow

1. Identify each active project/initiative, its business outcome, latest source date, project owner, delivery owner, and next milestone.
2. Read the latest implementation register or project report. Treat older local notes as context, not current status.
3. Separate outcomes from activity metrics. A meeting, draft, or training session is not a completed business result unless the agreed acceptance evidence exists.
4. Surface external dependencies explicitly: client decision, data, access, integration owner, vendor response, or resource availability.
5. Identify cross-project person/date collisions and single-person dependencies. Do not infer individual performance from mention counts or activity volume.
6. Rank work by hard dates, customer/business impact, dependency criticality, and reversibility. Explain the reason for each top priority.
7. Produce an owner-ready weekly view and a short list of decisions/asks for leadership.

## Output

Provide:

- `组合摘要`: key changes since last review and overall pressure points.
- `项目表`: project, desired result, current evidence, next milestone, accountable owner, external dependency, risk, next action.
- `资源冲突`: named people and overlapping commitments, with evidence.
- `本周三项优先`: no more than three outcomes, each with owner and proof of completion.
- `需要拍板`: decision, decision-maker, options, recommendation, and deadline; mark unknown fields as unknown.

## Boundaries

- State the as-of date for every status snapshot.
- If sources conflict, show the conflict and use the most recent authoritative source only when its authority is clear.
- Do not create tasks, reassign people, alter dates, or contact stakeholders unless explicitly requested.
