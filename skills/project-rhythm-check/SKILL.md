# 项目进度体检与推进节奏

## 一句话
**先查数据有没有，再谈进度。** 三个源可能全是空的，而「空」本身就是最有价值的第一条结论。

## 第 0 步：盘点数据源（不许跳）

并行查四件事，用真实返回说话：

| 源 | 怎么查 | 空的表现 |
| --- | --- | --- |
| 本工作区 | `ls -la <workspace>` | 只有 `.` / `..` |
| 项目事项库 | `mcp__wb-issues__todo_list`（scope=all, limit=200）+ `project_members` | `total: 0`；成员可能只有本人 |
| 项目资料盘 | `mcp__netdrive__tdrive.dir_list`（dir_id = tdrive root） | 只有系统目录 + 一份《资产库使用指南》 |
| 飞书侧（真实进度所在） | 看当前会话有没有飞书连接器 | connector-status 里没有 → 拉不到 |

**坑**：本机 `~/WorkBuddy/<其他日期工作区>/.workbuddy/memory/*.md` 里的日志**往往与当前项目无关**（可能是磁盘清理、Notion 盘点、代注册之类）。读之前先看标题，别把无关日志当成项目进度。

**四源全空时的正确写法**（不要含糊过去）：
> 进度事实不在本地，也不在项目事项库。这是一个结构性缺口，本身就是要修的第一件事——项目进度没有单一事实源，每天靠人脑与聊天记录拼。

然后补一句：下文体检基于用户档案/近期记录**推导**，标注「待线上复核」。

## 第 1 步：进度体检（按紧迫度重排，不按归属罗列）

从用户长期档案 + 近期工作记录里抽基线，列成一张表：

| 优先级 | 项目/工作线 | 状态（带日期） | 最大风险 | 距下一个硬节点 |

判定规则：
- **P0** = 24–48 小时内无外部依赖的硬节点（演示、激活、验收、汇报）
- **P0** = 当天出结果的批量交付 QA（失败项要当天分派）
- **P1** = 客户健康度相关、未闭环的客户诉求
- **P2** = 活动策划、材料包、技术收尾（可推迟）

**关键判断句式**：今天只有 P0 的 X 值得动用全部注意力；P1/P2 今日只做「不让它变红」的最小动作（回一句话、交一份问卷），不做推进。

## 第 2 步：节奏建议（三段式 + 原则）

原则先写，且要短到能背：
1. **T-1 只做不可逆项和冻结项**，不再新增任何范围。
2. **单点必须双备份**——关键人今天指定 back-up，并让 back-up **实操一次**（不是口头交接）。
3. **材料先过门禁再外发**，避免现场临时改口径。
4. **成败指标前置确认**——会开完 ≠ 成功，指标动了才算；T-1 写死采集口径（定义 / 取数时间点 / 取数人）。

| 段 | 时间 | 唯一目标 | 完成标志 |
| --- | --- | --- | --- |
| T-1 | 今天 | 冻结：文案、名单、材料、口径 | 明天不再需要你决策 |
| D-Day | 硬节点当天 | 执行：到场、开跑、当场采集 | 基线数值落地 |
| T+2 / 节后 | 收尾与兑现 | 结账：QA 结果 + 卡点清单 | 卡点变成有主有期的清单 |

## 第 3 步：行动清单（可直接执行版）

**每条必须写到「到人、到点、到完成口径」**，缺一项就不算执行版：

| # | 动作 | 责任人 | 截止 | 完成口径（什么算做完） |

- 责任人用简称（你 / 客户对接人 / 设计），但**不能留空**；不确定的写「待认领」并单独列出。
- 完成口径要写成**可观测的事实**（「对方回确认」「群里发出数字」），不要写「推进了」「跟进了」。
- 截止时间带具体钟点，并**从当前时刻往后排**，而不是从早上 9 点排。

再补一个**今日时间块表**（当前时刻起 4 个块），每块给出交付物。

## 第 4 步：D-Day 分钟级时间轴

08:30 到场冒烟 → 09:00 预热 → 09:10 开场 → 09:20 演示 → 09:40 第一批 → 10:30 第一次数据快照 → 14:00 第二批 → 16:30 第二次快照 → 17:00 公布数值 → 18:00 当日复盘。

**必须附「未达标预案」**：不喊口号，落到「还差多少人、谁去盯、明天几点补」。

## 第 5 步：卡点消解矩阵

| 卡点 | 今天解还是节后 | 今日动作 | 责任人 |

分流规则：**当天能闭环的当天解**（补验收标准、指定 back-up、加材料门禁）；**涉合同/法务/付款的一律节后且只记录差异、不自行裁定**；**精力错配类只做收敛**。

## 第 6 步：成品话术（纯净可复制）

用户的「话术」= 可整段复制直接发出的成品。规则：
- 用代码块包住，正文里**不含**内部方案、不含「待确认/我方建议」、不含「请先核实」。
- **分对象给**：谁发（我方 / 客户信息化侧 / 客户管理员）就按谁的视角写，人称跟着换。
- 标准五段：激活/通知文案、当日预热、催办关键人、客户诉求回应（给路径不给功能承诺）、对外材料自检 3 问（成本报价？内部人员判断？未确认的承诺？）。

## 第 7 步：待确认 + 下一轮

列 3 条**必须现在问**的问题（每条附「为什么现在必须问」），外加「下一轮可交付」清单，等用户说「继续」。

## 边界（硬约束）

- **默认不写事项库、不改项目资料盘**。行动清单先以文档形式给出，是否写进 tracker 由用户点头。
- 对外材料里不做任何未授权承诺（范围 / 排期 / 价格）；涉合同问题指向对应负责人。
- 区分内部信息与客户可见信息，外发前跑自检 3 问。

## 产出模板（九节，可直接套）

1. 检查结论：数据源盘点表
2. 进度体检：P0–P2 表
3. 节奏建议：原则 + 三段表
4. 行动清单：到人到位到口径 + 今日时间块
5. D-Day 分钟级时间轴 + 未达标预案
6. 卡点消解矩阵
7. 成品话术（代码块）
8. 待确认 3 条
9. 下一轮可交付
