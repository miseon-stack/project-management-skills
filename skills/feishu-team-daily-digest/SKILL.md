# 团队日报横向梳理

把《服务商飞书 CSM&FDE-团队工作日报》当成**观测面**（不是考核表）：从中提取产能节奏、人员梯队、客户分布、长线风险，输出可讨论的梳理文档 + 节点地图。

与 `feishu-daily-report` 的分工：那个 skill 写**本人**的日报；本 skill 读**全团队**日报做横向分析。

## 数据源

- Base `<TOKEN>` / table `<TABLE_ID>`
- 字段：`提交人`（user 数组）、`日报提交日期`、`今日工作总结`、`明日工作计划`、`遇到的问题`、`AI汇总`

## 一次性拉全

```bash
lark-cli base +record-list \
  --base-token <TOKEN> \
  --table-id <TABLE_ID> \
  --format ndjson --output /tmp/daily_all.ndjson --overwrite --as user
```

**坑：`--format ndjson` 每行已是扁平 record 对象**（`record_id` + 字段名**平铺**在顶层），不是 `{fields:{...}}` 结构。用 `r.get('提交人')` 取，用 `r['fields']` 会全部取空。

解析模板：

```python
import json, collections
rows = []
for l in open('/tmp/daily_all.ndjson', encoding='utf-8'):
    l = l.strip()
    if not l: continue
    try: r = json.loads(l)
    except: continue
    if isinstance(r, dict) and 'record_id' in r: rows.append(r)   # 只收真记录行

def nm(r): return ','.join(p.get('name', '?') for p in (r.get('提交人') or []))
def dt(r): return (r.get('日报提交日期') or '')[:10]
```

## 四个统计维度（每次都要跑全）

| 维度 | 方法 | 产出 |
|---|---|---|
| 产能节奏 | 按 ISO 周聚合条数 | 周度表 + 日均（识别"假期周总量低但日均最高") |
| 人员梯队 | 人 × 周矩阵 | 首现/末次/条数，识别**新进批次**与**断更人** |
| 客户分布 | 客户名词表命中计数 | 梯队表 + Top4 集中度占比 |
| 主题权重 | 主题词表命中计数 | 判断主业是什么、是否衰减 |

- 客户词表：以当期在服务的客户名单为准（示例：客户A/客户B/客户C/客户D + 其他在服务客户）…（按当期实读补充）
- 主题词表：培训/豆包/多维表格/审批/迁移/认证/妙记/健康度/三灯/渗透率/工作坊/AI 先锋/上线验收/Customer 360
- **团队是混编日报**：客户B侧的CSM同事、FDE同事也会提交到同一张表 → 归类时单列一组，不要当成 CSM。

## 阶段归集

按周区间切 4 段（成型 / 铺开 / 交付与活动 / 节前收口），每段提炼 3–6 个节点事件。阶段边界以**实际出现的转折**为准（启动会、上线、入职、定性），不要机械按周切。

## 输出文档骨架

写入 `产物/<日期>_团队日报梳理.md`：

1. 总量与节奏（周度表）
2. 团队演进四阶段
3. 人员与梯队（含"⚠️ 断更"标注）
4. 客户全景梯队
5. 长线主题权重
6. 跨周期观察（**信号清单**：长线风险 / 流程堵点 / 产能饱和 / 覆盖收缩 / 单点依赖 / 节后节点）
7. 我的位置（本人）

口径：**横向归集与信号识别，不评价个人绩效**——文档开头必须写这句。

## 节点地图可视化

用 `widget_guidelines` 加载 `diagram` 模块后 `show_widget`，**出两张**：

1. **主干节点地图**（SVG 纵向时间线）：四阶段分组 + 10 个左右节点，spine 竖线 + 每节点小圆点。颜色**只用 2 个 ramp**：蓝（里程碑/交付）/ 琥珀（风险预警），灰作中性（人员/常规）。底部放图例。
2. **节后冲刺地图**（HTML 2×2 卡格）：顶部一条"假期空档"提示条 + 硬节点卡片，左侧 3px 色条标压力（amber 峰值 / blue 常规）。

★**中文宽度公式**：SVG 里中文文本宽度 ≈ font-size × 字数（**不是** 6px/字）。680 宽的图内 13px 正文最多约 **38 个中文字**——排节点文本前先按这个估，否则右侧溢出。

两图之间必须插一段 prose 过渡；节点地图是**inline 展示**，不必落地成文件（用户要归档时再补 HTML）。

## 关系图谱可视化（节点 ≥ 12 时必用）

**判断**：手绘固定坐标 SVG 在节点 >12 时必然糊（边交叉不可控）。此时**换载体**——落一个自包含 HTML（`产物/<日期>_团队协作知识图谱.html`），手写力模拟 + SVG 渲染，**零 CDN 依赖**（离线可开）。

### 先算两类边

```python
# ① 内部共现：同一条日报里同时被提及的两人，计一次
for r in rows:
    hit = set(p for p in PPL if p in txt(r))
    for x, y in itertools.combinations(sorted(hit), 2): edge[(x, y)] += 1
# ② 我方 → 客户方：某成员与某客户关键人同条出现
for r in rows:
    hs = set(e for e in EXT if e in txt(r))
    for o in OWN:
        if o in txt(r): for e in hs: pair[(o, e)] += 1
```

- 内部边保留 `w>=2`（噪声边会糊）；对外边 `w>=2` 全留但**按权重分级着色**。
- 词表分两张：我方成员表（PPL）+ 客户方关键人表（EXT，带 client 归属，用于二部图着色）。

### ③ 人 × 项目投入边（**做"贡献"必算**）

```python
# 某成员在该项目上"出没"的日报条数（同一条可计入多个项目）
for r in rows:
    a = nm(r)
    for j in PROJECTS:
        if j in txt(r): M[a][j] += 1
```

- 项目词表必须**先跑词频再定**，取 `条数 >= 阈值` 的进矩阵（本期 17 个项目 / 共 647 条），否则列数爆炸、矩阵没法看。
- 项目名要合并同义（"客户A"并入"客户A"）。

### 贡献的 4 个正交指标（**禁止只看提交条数**）

| 指标 | 算法 | 意义 |
|---|---|---|
| 提交条数 | 该人记录行数 | 出勤强度 |
| 产出字符数 | `len(今日工作总结)` 累加 | 输出体量 |
| 覆盖项目数 | `M[a]` 中非零项数 | 广度 |
| 触及量 | `sum(M[a].values())` | 项目侧影响力 |

实测反例（本期）：本人 24 条 / 20478 字 / 仅覆盖 4 项（深度型）；FDE同事 25 条 / 4389 字 / 覆盖 14 项（广度型）。**只看条数会把两种完全不同的贡献判成同一档。**

### 六种视图各解决一个问题

| 视图 | 读什么 | 适用 |
|---|---|---|
| **力导向** | 聚类自动浮现，边长反比于关系强度 | 看整体结构、找子群 |
| **同心圆** | 按被提及次数分环，环心=枢纽 | 看层级与单点 |
| **邻接矩阵** | 格色=共现次数，密网最准 | >10 节点、想看确切数字 |
| **项目网络**（异构图） | 项目固定在环上、成员在圈内 | 看谁横跨多项目、谁专精一条线 |
| **贡献矩阵**（人 × 项目） | 格=该人该项目的产出条数 | 量化贡献、找单点主责 |
| **二部图** | 我方在左、对方在右，按归属着色 | 看对接集中度与接口是否唯一 |

实测：**11–13 人规模下邻接矩阵最清晰**，力导向次之，同心圆只在中外环人数均衡（如 1/4/6）时才不显散。二部图 60+ 边必须分级着色，否则是毛线球。

### 异构图（人 + 项目）的工程口径

- **29 个节点 + 90 条边不能全放飞**：项目节点 `fixed=true` 排在椭圆环上（按产出总量降序），人节点在内圈自由受力 → 越靠中心说明横跨项目越多。全放飞必然糊成一团、标签互相压。
- **各图必须各自一套力参数**，共用会互相毁掉：

| 图 | rep | grav | pad | 边样式 |
|---|---|---|---|---|
| 内部 11 人 | 13000 | 0.006 | 40 | 统一灰 `#9A988F` + 粗细分级 |
| 项目异构 29 节点 | 24000 | 0.0035 | 60 | 四级：≥10 蓝粗 / ≥5 浅蓝 / ≥2 灰 / 1 极淡 |

- 人—人之间额外加 16 的碰撞间距，否则同岗成员会挤成一堆。
- ★**弱边理想长度必须封顶**：`L = max(105, min(178, 245 - w*12))`。不封顶时，只有 1–2 条弱连接的新人会被弹簧甩到画布边缘，看起来像被孤立（本期FDE同事即如此，虽属真实信息但距离失真）。
- 贡献矩阵用**行 = 项目、列 = 人**：两侧标签都能横排（SVG 不支持旋转文字），列底加合计行 = 个人触及总量。
- **项目二部图要按职能分组排序**（运营→CSM→FDE→客户B），同组人的边会自然成束；成员乱序时 100+ 条边必成毛线球。弱边（w≤2）透明度压到 **0.14** 并转灰 `#DEDCD3`，只让强边说话。

### 落地坑

- **图例要跟着视图换**：贡献矩阵是热力图，若沿用「运营/CSM/FDE」分组图例就是误导 —— 必须换成刻度图例（0 / 1–2 / 3–5 / 6–10 / 11–19 / 20+），并在右侧补一行"列=成员·行=项目"的读法说明。
- **图例 key 必须与配色 map 的 key 完全一致**。写 `setLeg(GC,['…','客户B线'])` 而 `GC` 里只有 `客户B` → `map[k][0]` 抛 `Cannot read properties of undefined (reading '0')`，且报错不会阻断渲染、界面看不出来（只少几个色块）。改法：`setLeg(GC,keys,labels)` 传显示名映射。
- SVG 里**不能用 `class="c-*"`** 配色类，必须每个 shape 显式 `fill` / `stroke`。
- 中文文本宽度 = `font-size × 字数`；680 宽图内 13px 正文约 38 字上限。
- 拖拽用 `pointerdown/move/up` + `setPointerCapture`，坐标换算经 `svg.getBoundingClientRect()` 与 `viewBox.baseVal` 比例。

## 常见结论模板（真跑出来的，供参照不要照抄）

- 健康度/三灯类风险往往是**长线**（预警→定性可能隔三周），不是月末突发 → 找最早的预警日期。
- 新进人员**全部以认证体系为主线**培养 → 说明在做建制化扩编。
- 主题权重里"培训"若长期占首位且不衰减 → 团队负荷被培训占满，与客户侧"缺人"诉求是同一件事的两面。
- 横切事务（工作坊 / 招聘 / 三灯口径 / 知识库）若集中在**一个人**身上 → 与客户侧的"单点依赖"是同类结构风险。
- **单人主责项目**要单独标出来：某项目 >50% 的产出挂在一个人身上（如本期某客户 23/42）→ 该人休假/离职即断。
- **一对固定搭档扛多个项目**（如本期某几个客户全由同一对成员承担）→ 是比"单人单点"更隐蔽的双人单点。
- 运营岗在客户项目上的产出量可能**高于**该项目的 FDE（本期某运营同事在某客户 24 条 > 某 FDE 20 条）→ 别按岗位想当然分配贡献。
