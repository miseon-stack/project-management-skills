# Project action brief

Convert source material into a concise, reviewable action brief. Keep source facts, proposed actions, and unresolved questions distinct.

## Workflow

1. Read the supplied notes and, when present, the latest relevant project plan or task register. Prefer current project sources over old summaries.
2. Extract decisions, deliverables, named owners, dates, client-side dependencies, risks, and explicit boundaries. Preserve exact names and dates from the source.
3. Create one action per independently verifiable outcome. Do not turn discussion topics into commitments unless the source records agreement.
4. For each action, include: action, accountable owner, collaborators, due date or “未定”, completion evidence, dependency, and source reference.
5. Highlight missing owner/date/acceptance criteria as unresolved rather than guessing. Distinguish client actions from provider actions.
6. Add a short “decision needed” section containing only items that require a person with authority to choose or approve.

## Output

Start with a brief status sentence, then use a table with columns: `动作｜主责｜协作｜期限｜完成证据｜依赖/风险｜来源`. Follow with `待决策` and `待确认` lists when needed.

## Boundaries

- Never claim an item is complete based only on a proposal or draft.
- Never invent dates, owners, customer approvals, or implementation status.
- Keep scope boundaries and customer-owned dependencies visible.
- This skill drafts artifacts only. Do not send messages, create tasks, or write to live project systems unless the user explicitly asks for that action.
